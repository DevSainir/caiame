# Резервные копии

## Что и куда

Каждый запуск кладёт в бакет R2 один зашифрованный архив `caiame-<метка времени>.tar.age`,
внутри два файла:

* `db.dump` — дамп базы в собственном формате Postgres (`pg_dump --format custom`), из него
  можно восстанавливать выборочно;
* `env` — серверный `/opt/caiame/.env`. Без него восстановленная база бесполезна: не
  поднять ни сессии, ни доступ к самой БД.

Раскладка по папкам:

| когда | куда |
| --- | --- |
| каждый день | `daily/` |
| воскресенье | `daily/` и `weekly/` |
| первое число | `daily/` и `monthly/` |

Недельная и месячная копии делаются **копированием внутри хранилища**, а не повторной
заливкой: не тратится исходящий трафик сервера, и все копии побайтово одинаковы.

**Сроки хранения задаются правилами жизненного цикла в самом R2.** Задание не удаляет
ничего и не должно — иначе правило окажется в двух местах и разойдётся.

## Расписание

Таймер systemd, ежедневно в 03:00 UTC со случайной задержкой до пяти минут.
`Persistent=true`: если сервер в это время был выключен, запуск произойдёт после старта —
иначе выключенная на сутки машина молча теряет день истории.

```bash
systemctl status caiame-backup.timer
systemctl list-timers caiame-backup.timer
journalctl -u caiame-backup.service -n 50
```

## Шифрование

Архив шифруется `age` перед отправкой; в хранилище не попадает ничего открытого.

Ключ лежит на сервере в `/opt/caiame/backup-age.key` с правами `600`. Это файл ключа, а не
парольная фраза: age в парольном режиме требует терминал и из таймера не запускается.
Модель доверия та же — один секрет, который и шифрует, и расшифровывает.

> **Копия ключа обязана существовать вне сервера.** Он одновременно единственный способ
> прочитать бэкапы. Сгорит машина вместе с ключом — сгорят и копии, и восстанавливать будет
> нечем. Держите его в менеджере паролей.
>
> Обратная сторона выбранной схемы: кто получил сервер, тот получил и все бэкапы за всю
> историю. Это осознанный размен на простоту.

## Проверка восстановлением

По воскресеньям, сразу после недельной копии, задание **скачивает архив обратно из R2**,
расшифровывает и разворачивает в одноразовый контейнер Postgres. Проверяется именно то, что
лежит в облаке, а не то, что осталось на диске сервера.

Проверка считает строки в `courses`, `specializations`, `accreditations`, `users` и падает,
если каталог пуст: успешный `pg_restore` сам по себе ещё ничего не значит — дамп пустой
схемы развернётся без единой ошибки.

Оба отказа проверены на живом бакете: испорченный архив ловится аутентификацией age,
целый архив с пустой базой — отсутствием таблицы `courses`.

Запустить проверку вручную:

```bash
cd /opt/caiame && PYTHONPATH=ops/backup python3 ops/backup/backup.py --verify
```

## Восстановление

Инструмент по умолчанию ничего не трогает: скачивает, расшифровывает, раскладывает файлы и
останавливается. Развернуть в базу можно только явным `--into`.

```bash
cd /opt/caiame
export PYTHONPATH=ops/backup

python3 ops/backup/restore.py --list                 # какие копии есть
python3 ops/backup/restore.py                        # последняя из daily/ в /tmp/caiame-restore
python3 ops/backup/restore.py --key weekly/caiame-20260830T030000Z.tar.age
python3 ops/backup/restore.py --into caiame          # развернуть поверх рабочей базы
```

`--into` разворачивает с `--clean --if-exists`, то есть **стирает текущее содержимое базы**.
Сначала посмотрите распакованный `db.dump` и `env`, потом решайте.
