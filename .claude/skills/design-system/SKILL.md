# Дизайн-система

Токены восстановлены из макета Figma статистически: собрана гистограмма фактических
значений, близкие схлопнуты, шкала выведена из частотности. Полная история — в
`docs/tokens-mapping.md`, исходные данные — в `design-audit.json`.

**Единственный источник правды — `frontend/tailwind.config.js`, и он генерируется.**
Руками его не правят: правится `tokens.json`, после чего запускается
`node tools/design-tokens/tailwind.mjs`. Правка конфига руками потеряется на следующей
генерации, и это заметят не сразу.

## Главное правило

**Произвольных значений в классах нет.** `p-[7px]`, `text-[13px]`, `bg-[#3B82F6]`,
`w-[240px]`, `style="margin-top: 4px"` — запрещены все. То же про цвет в любом виде:
hex в шаблоне, в `<style>`, в атрибуте `fill` у инлайнового SVG.

Если нужного значения в шкале нет — **остановись и спроси**. Не подбирай ближайшее
молча и не изобретай новое. Отсутствие значения означает одно из двух: либо токен
действительно нужен и его надо завести осознанно, либо в макете в этом месте случайный
мусор, и правильный ответ — ближайший существующий токен. Различить эти два случая может
только человек, у которого перед глазами макет.

Проверка машинная и обязательная:

```bash
cd frontend && npm run lint:tokens
```

Она валит сборку на произвольных значениях, инлайновых стилях с числами и цветами, сырых
hex и на классах вроде `bg-blue-500`, которых в теме больше нет — такой класс не даёт
ошибки сам по себе, он просто молча ничего не красит. У линтера есть самопроверка
(`npm run lint:tokens:self-test`), она держит его честным.

## Шкала

### Цвета

Дефолтная палитра Tailwind **выключена целиком**. Существуют только:

* `primary` 50…950 — акцент, `primary-500` = `#2178ff` из макета, `primary-950` = `#002051`.
* `neutral` 50…950 — текст, фоны, обводки. Из макета: 50, 100, 400, 500, 600, 900.
* `success` 50…950 — `success-500` = `#61c000`.
* `danger` 50…950 — `danger-500` = `#ff4a4a`.
* `white`, `transparent`, `current`, `inherit`.

Ступени, которых не было в макете, достроены интерполяцией — они настоящие и ими можно
пользоваться, но в `docs/tokens-mapping.md` помечено, какие пришли из макета, а какие нет.

Поверх палитры лежат семантические роли, и **в вёрстке предпочитай их**:

| класс | значение | для чего |
|---|---|---|
| `text-ink` | neutral-900 | основной текст |
| `text-muted` | neutral-700 | вторичный текст, подписи |
| `text-subtle` | neutral-600 | третьестепенное: даты, счётчики — **только от 18px или для нетекстовых элементов** |
| `text-disabled` | neutral-400 | выключенное состояние |
| `text-inverse` | white | текст на тёмном и на акценте |
| `text-accent` | primary-600 | ссылки, активное состояние |
| `bg-page` | white | фон страницы и карточек |
| `bg-subtle` | neutral-50 | подложка секции, зебра |
| `bg-accent` | primary-500 | основная кнопка |
| `bg-inverse` | primary-950 | тёмные секции |
| `border` | neutral-400 | обводка по умолчанию |
| `border-subtle` | neutral-100 | разделители |
| `border-accent` | primary-500 | фокус, выделение |

Роль говорит, **зачем** цвет, а ступень — только какой он. `text-muted` переживёт смену
палитры, `text-neutral-600` — нет.

**Текстовые роли на ступень темнее макета, и это осознанно.** Серые, которыми в макете
набран текст, дают 2.85:1 и 3.79:1 на белом при пороге WCAG AA 4.5:1 — то есть мелкий серый
текст физически нечитаем. Палитра при этом не тронута: сдвинулось только то, на что смотрят
роли. Если сверяешься со скриншотом и видишь, что серый чуть темнее макета — так и задумано,
не «чини». Единственная роль ниже порога — `text-subtle` (3.79:1), она годится для крупного
текста и подписей, но не для основного.

### Типографика

Шрифт один: `font-sans` — Manrope. `text-*` уже несёт свой line-height и
`letter-spacing: -0.03em`, отдельно их ставить не нужно.

> **ВРЕМЕННОЕ РЕШЕНИЕ: Manrope грузится с Google Fonts** — `<link>` в `frontend/index.html`.
> Перед продом заменить на локальные `woff2` (веса 400/500/600/700) в `src/assets/fonts/`.
> Пометка продублирована крупным блоком в самом `index.html`.

| класс | кегль | line-height | где встречается в макете |
|---|---|---|---|
| `text-2xs` | 10px | 1.5 | бейджи, мелкие подписи |
| `text-xs` | 12px | 1.5 | статусы, служебный текст |
| `text-sm` | 14px | 1.6 | кнопки, подписи полей |
| `text-base` | 16px | 1.6 | основной текст |
| `text-lg` | 18px | 1.6 | крупный текст |
| `text-xl` | 20px | 1.6 | заголовок карточки |
| `text-2xl` | 24px | 1.3 | заголовок секции |
| `text-3xl` | 28px | 1.3 | заголовок экрана |
| `text-4xl` | 32px | 1.3 | крупный заголовок |
| `text-5xl` | 38px | 1.3 | заголовок главной |

Начертания: `font-regular` (400), `font-medium` (500), `font-semibold` (600), `font-bold` (700).
В макете чаще всего 600 — это рабочее начертание интерфейса, а не исключение.

Отдельные `leading-tight|snug|normal|relaxed` (1.3 / 1.5 / 1.6 / 1.8) существуют для случаев,
когда нужен другой интерлиньяж при том же кегле. `leading-relaxed` — для длинных описаний,
в макете он используется осознанно.

### Отступы

Шкала в шагах по 4px, ключ умножается на 4: `p-4` = 16px, `gap-6` = 24px.

Доступны: `0, 2, 3, 4, 5, 6, 7, 8, 10, 12, 14, 15, 18, 24, 25, 28, 35`
(= 0, 8, 12, 16, 20, 24, 28, 32, 40, 48, 56, 60, 72, 96, 100, 112, 140 px).

**Дыры в шкале намеренные.** Нет `1` (4px), нет `9`, `11`, `16`, `20` — этих значений не
было в макете. Понадобилось — это разговор, а не догадка.

Самые частые: 24px (`6`), 16px (`4`), 60px (`15`), 40px (`10`). Расстояния больше 160px
в шкалу не вошли: это раскладка страницы, а не отступ между элементами.

### Форма

Радиусы: `rounded-xs` 2px, `rounded-sm` 4px, `rounded-md` 8px, `rounded-lg` 12px,
`rounded-xl` 20px, `rounded-full`. Чаще всего в макете — 4px (71 использование).

**Кнопки, поля ввода и полоски прогресса — `rounded-full`, а не числовой радиус.** В макете
у них радиус ровно в половину высоты (22px при высоте 45px), то есть это «таблетка».
Написать `rounded-xl` вместо `rounded-full` — заметная ошибка вёрстки, кнопка перестаёт быть
кнопкой этого проекта.

`rounded-xl` (20px) — единственная ступень для больших контентных карточек. В макете они
скруглены на 18, 20 и 24px на разных экранах; это одна и та же карточка, разница невидима.

Обводки: `border` 1px, `border-2` 2px, `border-0`. Больше в макете не встречается.

Ширины: `max-w-container` 1240px — контентная колонка при полях 100px,
`max-w-card` 466px — карточка входа и регистрации.

## Чего в шкале нет намеренно

* **Теней нет и не будет** — в макете нет ни одного `DROP_SHADOW`, и это подтверждённое
  решение, а не пробел. Никаких `shadow-*` в вёрстке.
* **Группы `warning` нет** — в макете нет ни одного жёлтого или оранжевого. В `tokens.json`
  шкала лежит с пометкой `invented` и в конфиг не попадает. Она понадобится позже; когда
  дойдёт до предупреждений — спроси цвет, не бери жёлтый на глаз.
* **Брейкпоинтов своих нет** — работают дефолтные Tailwind. В файле ровно одна ширина
  артборда (1440px), выводить лестницу не из чего; мобильную версию собираем вручную.
* **Нет токенов на hover, focus, анимации и z-index** — этих состояний в макете не нарисовано.
  Каждый такой случай проговариваем отдельно. На главной уже применено соглашение:
  наведение на кнопку затемняет её на одну ступень (`hover:bg-primary-600`,
  `hover:bg-success-600`). Это придумано при вёрстке, а не взято из макета.

## Компоненты

Раскладка папок — из скилла `frontend-architecture`: переиспользуемые атомы в
`src/core/components/`, доменные — в `src/features/<name>/components/`.

**Перед тем как писать новый компонент, посмотри, что уже есть:**

```bash
ls frontend/src/core/components frontend/src/features/*/components
```

Похожий компонент почти всегда уже написан, и правильный ход — расширить его пропсом, а не
завести второй такой же с другим именем. Две кнопки с разными названиями — это не два
компонента, это будущий баг вёрстки.

Именование:

* Атомы в `core/components/` — с префиксом `Base`: `BaseButton.vue`, `BaseInput.vue`,
  `BaseContainer.vue`. Префикс сразу говорит, что компонент ничего не знает о предметной области.
* Глобальный каркас страницы — с префиксом `App`: `AppHeader.vue`, `AppFooter.vue`.
* Иконки — с префиксом `Icon` в `core/components/icons/`: `IconArrowUpRight.vue`. Внутри
  только `fill="currentColor"` — цвет задаётся классом `text-*` на месте применения.
  Хардкод цвета в SVG линтер завалит, и правильно сделает.
* Доменные — по сущности, без префикса: `CourseCard.vue`, `LessonList.vue`.
* Имя всегда из двух слов минимум и в `PascalCase`. `Card.vue` конфликтует с HTML-мышлением
  и ничего не сообщает.
* Варианты — пропсом (`variant="primary|secondary|ghost"`), а не отдельным файлом.

Ограничения из `CLAUDE.md` действуют: `.vue` не длиннее 250 строк, пропсы не мутируются,
состояние компонента живёт в компоненте.

**Высоту кнопок и полей не назначай числом.** Она получается из вертикального паддинга и
line-height — так элемент переживает смену кегля, а фиксированная высота ломает его молча.
Токенов на высоту в шкале нет намеренно.

## Как пересобрать токены

```bash
node tools/figma-extract/index.mjs --page "profile" --root-width 1440   # макет -> design-audit.json
node tools/design-tokens/build.mjs                                      # аудит -> tokens.json + таблица
node tools/design-tokens/tailwind.mjs                                   # tokens.json -> tailwind.config.js
```

Сырой ответ Figma кэшируется в `.cache/figma-raw.json`; `--refresh` перекачивает его заново.
Все три шага детерминированные: одинаковый вход даёт одинаковый выход, поэтому пересборка
безопасна в любой момент.
